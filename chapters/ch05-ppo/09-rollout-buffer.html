5.5 Rollout buffer and rollouts

Fresh answers in, used once, then thrown away

PPO learns only from answers the current model just produced, so it keeps a short-term notebook called the rollout buffer. It fills it, learns from it for a few passes, then wipes it clean. Old answers cannot be reused: once the model has changed, the safety math no longer holds for them.

Phase 1

Collect

The current model generates a batch of full answers and records each choice it made, ready to learn from.

→

Phase 2

Train

Run a few passes of small clipped updates over that batch, squeezing out the lessons without overusing them.

→

Phase 3

Purge

Erase the whole notebook. The model has moved on, so the old answers are stale and unsafe to reuse.

Think of it like a chef tasting today's batch of soup to adjust the recipe, then pouring it out. Yesterday's soup was made with a different recipe, so tasting it again would teach the wrong lesson.

In plain terms

RolloutOne full answer the model generates from a prompt, token by token, to the end.
Rollout bufferThe short-term store of the current batch, used for a few passes then emptied.
Generation bottleneckProducing fresh answers is slow, often most of the training time, because the buffer must be refilled every cycle.
