5.6 PPO for RLHF: the full loop

The whole method is one loop: generate, score, update, repeat

PPO does not learn from a fixed answer key. It learns from feedback on the model's own output, so it must keep producing fresh answers, judging them, and adjusting. Everything later in this chapter is a detail inside one of these four steps.

Step 1

Generate

The current model writes full answers to a batch of prompts. This is the slow part, often most of the wall-clock time.

→

Step 2

Score

A reward model rates each answer, giving a number for how good it is. This is the only feedback the model gets.

→

Step 3

Judge each choice

Work out which token choices were better or worse than expected, the advantage, so credit lands in the right places.

→

Step 4

Update, safely

Nudge the model toward the better choices, but only by a small, clipped amount so it cannot lurch too far.

Throw away the old answers generate fresh ones and run the loop again

In plain terms

On-policyThe model learns only from answers it just produced; old answers go stale and get discarded.
Reward modelA separate trained scorer that stands in for human judgement of answer quality.
