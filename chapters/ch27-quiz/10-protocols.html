How agents connect

What is MCP's N plus M architecture, and why does it matter?

Reveal ▸

Without a standard, N agents times M tools means N times M custom integrations. MCP standardizes the interface: each agent ships one client and each tool ships one server, so the total is N plus M. Build a tool once and any compatible agent can use it, like USB for agent-tool links.

How does A2A differ from MCP, and when do you need both?

Reveal ▸

MCP connects an agent to tools with defined schemas. A2A connects agent to agent for opaque task delegation, where you do not see the other agent's internals. A full system uses both: A2A coordinates between agents, and each agent uses MCP to reach its own tools.

What are MCP's four core primitives?

Reveal ▸

Tools execute actions and have side effects. Resources are read-only data. Prompts are reusable templates that help formulate calls. Sampling reverses direction, letting a server ask the client's LLM for help. The tools-versus-resources split matters for safety: reads are free, actions need approval.
