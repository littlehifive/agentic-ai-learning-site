28.10, 28.17, 28.18 · How agents connect

Two protocols, two different jobs

One connects an agent to its tools. The other connects agents to each other. They are complements, not rivals.

MCP

Agent to its tools

A standard way for an agent to discover and call tools and data, so any tool plugs into any agent.

  • Tools: actions with effects, like create or delete.
  • Resources: read-only data, like files or records.
  • Prompts: reusable templates for common tasks.
  • Discovery: the client asks the server to list what it offers.

A2A

Agent to agent

A standard way for separate agents to hand each other work and track it through to completion.

  • Agent Card: a public profile listing an agent's skills.
  • Task: a unit of work that moves from submitted to working to done.
  • Message and Artifact: what is said, and what is produced.
  • Push notifications: webhook updates for long jobs.

In plain terms

MCP vs A2AMCP gives one agent hands to use tools. A2A lets many agents talk and divide a job.
