21.6 Security model

You are handing an agent real capabilities

A connected tool can delete files, send messages, or run code. So MCP is built around a chain of trust: the user trusts the host, the host vets everything below it, and nothing further out is taken at face value.

Most trusted

Host

Trusted by the user. Sets the rules, asks for consent, and decides which servers may connect.

→

Trusted by host

Client

Carries out the host's rules and checks server replies before passing them on.

→

Trust, but verify

Server

Expected to behave, but its data is not blindly trusted; a bad one could hide instructions.

→

Untrusted

Outside services

Web pages, databases, and files the server touches. All of it must be validated.

Think of it like giving a house key to a contractor. You set the rules and stay in charge, you confirm anything irreversible before it happens, and you do not trust a note left by a stranger just because it appeared inside the house.

In plain terms

User consentThe host must ask before running a tool that changes things, and keep a log.
Prompt injectionHidden instructions inside data the model reads; treat all outside content as untrusted.
