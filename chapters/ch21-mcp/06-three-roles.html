21.2 Architecture overview: the three-role model

Three jobs: the host, the client, the server

MCP splits the work into three roles. The host is the app you run. Inside it, a client is the connector to one tool. On the other end, a server is the small program that actually exposes that tool or data.

Role 1

Host

The application the user actually opens and talks to. It runs the LLM, decides which servers to connect to, and enforces the security rules.

Like the dining room of a restaurant, where you sit and place your order.

Role 2

Client

A small connector inside the host. Each client holds one dedicated connection to one server and handles the back-and-forth messages. A host can run many clients at once.

Like the waiter who carries one table's orders to and from the kitchen.

Role 3

Server

A lightweight program that exposes one tool or data source, often just a thin wrapper around an existing API, database, or the file system. It is deliberately simple to build.

Like the kitchen that receives a ticket and actually cooks the dish.

In plain terms

One host, many clientsA single app can connect to many servers at once, each through its own client.
Servers stay thinThe hard protocol work lives in the host and client, so a server is easy to write.
