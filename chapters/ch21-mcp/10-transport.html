21.2 Transport layers

Two ways host and server actually talk

The protocol stays the same no matter how the messages travel. MCP defines two standard channels: one for tools on your own machine, one for tools running somewhere on the network.

Local

Standard input and output

The host launches the server as a child program on the same machine and talks to it through its input and output streams. Nothing touches the network, the server runs in its own process for isolation, and there is no setup. Best for file access, local code, and developer tools.

Remote

Streamable HTTP

The server runs as a normal web service. The host sends requests over HTTP and can receive a single reply or a live stream of partial results. This works through ordinary web infrastructure like proxies and firewalls, so it suits cloud-hosted and enterprise tools.

Think of it like talking to someone in the same room versus calling them on the phone. The conversation is identical; only the channel changes to fit the distance.

In plain terms

Transport-agnosticThe same messages work over any channel; the protocol does not care which.
Stateful sessionThe connection stays open, so setup happens once and the server can push updates.
