21.1 How MCP works, end to end

One question, routed to a tool and back in plain words

Say you ask, "What is in my notes file?" The model does not read the file itself. It asks the host to call a tool, the host routes the request to the right server, the answer comes back, and the model turns it into a normal reply.

Step 1

You ask

You type a request into the host application.

→

Step 2

Model decides

The LLM picks which tool can answer and with what inputs.

→

Step 3

Host routes

The host sends the call to the matching server.

→

Step 4

Server runs

The server does the work and returns a result.

→

Step 5

You read

The model phrases the result as a natural reply.

The protocol machinery stays hidden you only see the question and the answer

In plain terms

Tool callThe model's request to run a named action, with its inputs filled in.
RoutingThe host matching a tool call to the one server that offers that tool.
