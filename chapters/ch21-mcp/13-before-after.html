21.9 MCP versus custom integration

The same goal, with and without a shared protocol

Custom wiring can be quick for one fixed pairing, but it does not travel. A protocol costs a little more setup and pays it back the moment you add another tool, another agent, or another vendor.

Custom integration, per pairing

  • A new connector for every agent-and-tool combination
  • Locked to one model or vendor; switching means rewriting
  • Each team re-solves the same plumbing from scratch
  • Fine for a single fixed setup or quick prototype

MCP, one standard for all

  • Build a tool once; every compliant host can use it
  • Vendor-neutral, so no lock-in and easy to swap models
  • Tap a growing ecosystem of ready-made servers
  • Built-in sessions, live updates, and a consent model

In plain terms

Use MCP whenYour tools should work across many models or be shared with others.
Skip it whenOne fixed model, a quick prototype, or you need the lowest possible latency.
