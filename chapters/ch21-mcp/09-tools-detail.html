21.5 Tool definition and discovery

A tool is mostly a clear description

Tools are the heart of MCP. Each one is a short, structured definition. The model never sees the tool's code; it chooses a tool almost entirely from the name and the description, so vague wording leads to the wrong call or none at all.

What every tool definition contains

nameA unique label, such as search_codebase, the model uses to refer to it.
descriptionPlain language saying what it does, when to use it, and what it returns. This is what guides the model's choice.
inputSchemaThe list of expected parameters and their types, so the model knows how to fill in the call.
annotationsOptional safety hints, such as whether the tool only reads data or makes irreversible changes.
Think of it like labeling switches on a panel. "Search files by content" is a switch the model can confidently flip; "Search" leaves it guessing. The clearer the label, the fewer the mistakes.

In plain terms

DiscoveryWhen a host connects, it asks the server for its current list of tools.
Annotation hintA flag like "destructive" tells the host to ask the user before running the tool.
