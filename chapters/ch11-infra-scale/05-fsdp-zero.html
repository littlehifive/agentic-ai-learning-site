11.2.5 Fully Sharded Data Parallelism (FSDP / ZeRO-3)

Give each GPU only its own slice to hold

The plain way to use many GPUs makes every one keep a full copy of everything, which still overflows. Sharding flips that: each GPU permanently owns just one slice of the weights, gradients, and optimizer copies, and borrows the rest only for the split second it is needed.

No GPU holds the whole thing. For a 70B model this cuts the load from impossible to about 70 GB per GPU, which fits.

Think of it like a moving company splitting one enormous load across many trucks so no single truck is overloaded. When a heavy item needs assembling, the trucks briefly bring their pieces together, then go back to carrying just their share.

In plain terms

ShardingSplitting the model, gradients, and optimizer copies into slices so no one GPU holds it all.
FSDP / ZeRO-3The two common names for this: FSDP in PyTorch, ZeRO-3 in DeepSpeed. Same idea.
The tradeYou save huge amounts of memory, but GPUs must chatter more to gather slices when needed.
