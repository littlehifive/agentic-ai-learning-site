11.2.6 Combining Strategies

Each split solves a different squeeze

These methods are not rivals; real systems combine two or three. The choice follows a simple ladder: reach for the lightest one that makes the job fit, and add heavier ones only when you must.

Start here

  • Sharding (FSDP / ZeRO-3) is the default once a model passes a few billion parameters. It is the biggest memory saver per unit of effort.
  • Plain copies (data parallel) are enough only when the whole model already fits on one GPU and you just want to go faster.

Add when needed

  • Tensor parallelism when a single layer is too wide. Keep it inside one machine, eight GPUs or fewer, because of the heavy chatter.
  • Pipeline parallelism is the last resort, for the very largest models past 100 billion parameters that still will not fit any other way.
Think of it like moving house: first split the load across trucks (sharding). If one item is too big for a truck, carry it with several people side by side (tensor). Only call in a relay of trucks down the highway (pipeline) when nothing else works.

In plain terms

The ladderSharding first, then tensor parallelism, then pipeline parallelism, adding each only when the job still does not fit.
3D parallelismThe name for combining all three at once, common on the largest training runs.
