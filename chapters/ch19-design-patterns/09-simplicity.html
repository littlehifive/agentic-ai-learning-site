19.3 Design principles: keep it simple

Prefer the simplest thing that works

Autonomy is not free. It costs more calls, more latency, and is harder to debug. The book's first principle is plain: start with the simplest architecture, and add complexity only when you have shown the simpler one fails. A prompt chain that solves the problem beats a multi-agent system that might.

First try

A single prompt

One well-crafted call. Often enough on its own.

→

Then

A fixed workflow

Chain, route, or parallelize with a set control flow.

→

Only if needed

An autonomous agent

Let the model drive when the task truly demands it.

Think of it like a recipe versus a chef. A workflow is a recipe you follow step by step; an autonomous agent is a chef improvising. Use the recipe whenever it gets you there, and call in the chef only when the dish is genuinely novel.

TransparencyFavour designs whose every step you can inspect; opaque ones are hard to fix.
