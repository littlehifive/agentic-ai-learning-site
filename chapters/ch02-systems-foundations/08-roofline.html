2.1.7 Arithmetic Intensity and the Roofline Model

Every job is limited by one of two things

Recall the chip can do math much faster than it can fetch numbers. So any task is held back by whichever runs out first. If it spends its time waiting for data, it is memory-bound. If the math units are always busy, it is compute-bound. Knowing which one tells you what to fix.

Stuck waiting for data

Memory-bound

Little math per number fetched, so the math units sit idle while data trickles in. The fix is to move less data, or to reuse each number more.

Example: attention, the step where the model weighs earlier words. On a long text the GPU can be 60% idle, just waiting.

Math units kept busy

Compute-bound

Lots of math per number fetched, so the chip runs near full speed. The fix here is faster or cheaper math, like using smaller number formats.

Example: the model's big feed-forward layers, dense grid multiplications that keep every math unit working.

Think of it like a chef and a delivery van. If the chef is idle waiting for groceries, you need faster delivery (memory-bound). If groceries pile up while the chef cooks flat out, you need more chefs (compute-bound).

In plain terms

Memory-boundHeld back by how fast data can be fetched; the math units wait around.
Compute-boundHeld back by how fast the math runs; data is never the holdup.
