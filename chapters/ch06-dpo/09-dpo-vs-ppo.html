Reading the tradeoffs

Simpler than PPO, but hungrier for good pairs

DPO and PPO chase the same goal, alignment to human preference. DPO gets there with far less machinery, which is its great appeal. The catch is that it leans entirely on the quality of a fixed set of preference pairs.

DPO

  • Two models in memory: the policy and a frozen reference.
  • One ordinary supervised step, no reinforcement loop.
  • Far simpler and more stable to run and tune.
  • Learns off-policy, from a fixed dataset of pairs.
  • Only as good as those pairs; noisy labels poison it.

PPO

  • Four models in memory, including a separate reward model.
  • A reinforcement loop that generates and scores live.
  • More moving parts, heavier and trickier to keep stable.
  • Learns on-policy, from the model's own fresh answers.
  • Averages over many samples, so it tolerates noise better.
On-policy means PPO learns from text the current model just generated; off-policy means DPO learns from a pre-collected set of pairs. That fixed set is both DPO's simplicity and its main weakness.
