6.6 When DPO fails

The simplicity has a price

Because DPO learns from a fixed set of pairs rather than from the model's own fresh answers, its weaknesses all trace back to that dataset. Three show up most often in practice.

Noisy labels stick

If some pairs are mislabelled, DPO memorizes the mistakes. PPO averages over many live samples and shrugs off noise more easily.

No exploration

DPO can only learn from behaviours already in the data. It cannot discover a better answer that no pair ever showed it.

The data goes stale

As the model changes, pairs collected from an older version describe answers it no longer gives, so training drifts onto less relevant examples.

The fix in every case is the same: invest in clean, diverse preference pairs, and refresh them as the model evolves. With good data, DPO is hard to beat for the effort.
