20.2.3 Reward signal design

Grade by whether the task actually got done

The cleanest way to score an agent is execution-based reward: run the result and check it. Did the tests pass? Is the right item in the cart? You do not judge how nice the explanation reads. You judge the outcome, which makes the score hard to fake and perfectly aligned with success.

Reading the text

An agent can write a confident, well-worded answer that is simply wrong. Grading the words rewards polish, and a clever agent can talk its way to a high score without solving anything.

Running the result

Run the actual test suite, or inspect the final state of the world. It either works or it does not. There is no wording to hide behind, so the agent cannot game its way to a pass.

Think of it like grading an engineer by whether the bridge actually holds, not by how tidy the blueprint looks. A beautiful drawing earns nothing if the bridge falls down; a working bridge passes even if the sketch is rough.

In plain terms

Execution-based rewardScore by running the outcome and checking it, not by reading the agent's words.
Reward hackingScoring high without really doing the task; execution-based grading shuts this down.
LLM-as-judgeThe fallback when no test exists: a second model rates the result, flexible but pricier and less consistent.
