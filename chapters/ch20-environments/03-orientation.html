20.1 What this chapter is about

Two words to keep straight: the environment and the benchmark

An environment is the practice world the agent acts in. A benchmark is a fixed set of tasks in that world, run the same way every time, so different agents can be compared fairly. Environments serve two jobs at once.

✓ Training. The agent can try things, fail, recover, and learn, without harming any real system. The book calls this safe exploration.
✓ Testing. Every agent faces the same tasks under the same conditions, so a score from one lab can be reproduced in another.
✓ Curriculum. Tasks can ramp up in difficulty as the agent improves, just as people master the easy parts before the hard ones.
✓ A common interface. Reset to start, take a step to act, observe the result. The same loop fits coding, web, and desktop tasks alike.

In plain terms

EnvironmentThe world the agent works in: a browser, a computer desktop, a code repository.
BenchmarkA standard task set in that world, scored the same way so agents can be ranked.
