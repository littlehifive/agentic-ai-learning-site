25.2 The agent development lifecycle

The same four jobs, handed to you pre-built

Whatever framework you pick, it is solving the same handful of recurring jobs. Knowing these four makes every framework easier to read, because each one just makes different choices about how to do them.

The loop and orchestration

Call the model, read its tool requests, run the tools, feed the results back, and decide when to stop. The framework runs this cycle and decides how many steps and in what order.

State and memory

What the agent knows so far: the conversation, intermediate results, counters. The framework carries this between steps and, often, saves it so a long task can pause and resume.

Tools

The agent's hands: search, code, database calls. The framework standardises how a tool is described to the model and how its output comes back, including what happens when a tool fails.

Control and safety rails

Limits on how many tool calls are allowed, which sites it may visit, and where a human must approve. The framework gives you places to enforce these instead of trusting the prompt alone.

Think of it like a kitchen that comes with the stove, fridge, and plumbing already installed. You still decide the menu, but you are not laying pipe before you can cook.
