25.5 Agent testing and evaluation

The same input can give a different answer

Ordinary software is predictable: the same input gives the same output, so a test either passes or fails. Agents are not like that. The model can phrase things differently, pick a different tool, or take a different number of steps. Testing has to check that the behaviour is right, not that the text matches exactly.

Think of it like grading an essay instead of a multiplication table. You cannot check it against one correct string. You check whether it used good sources, stayed on topic, and reached a sound conclusion.

In plain terms, what makes it tricky

Non-deterministicThe output varies run to run, so exact-match tests are too brittle.
Stateful and multi-stepA failure can come from any step in a long chain, not just the final answer.
Trajectory mattersYou test the path it took (which tools, in what order), not only where it ended.
