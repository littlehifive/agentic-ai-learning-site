25.1 Motivation: the engineering gap

A demo in a notebook is easy. A reliable agent is not

A quick agent assumes a friendly world: clean inputs, working tools, and a human ready to restart it. A real agent gets none of that. It must survive failures, leave a trail you can inspect, be testable, and run for minutes without a babysitter. That gap is what frameworks were built to close.

Think of it like the difference between a go-kart you push around a parking lot and a car that has to pass inspection, survive the highway, and start every morning. Same basic idea, vastly more engineering underneath.

In plain terms, what production demands

ReliabilityRecover from a failed tool or a stuck loop instead of crashing.
ObservabilityA record of every model call and tool use, so you can see why it did what it did.
Testability and iterationA way to check behaviour and to improve it as the world changes.
