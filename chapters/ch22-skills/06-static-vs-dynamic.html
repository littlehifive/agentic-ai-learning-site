22.2 Skill architecture patterns

Load every skill always, or only the ones the task needs

Each loaded skill takes up room in the agent's limited context window. So the central choice is timing: keep all skills on at all times, or fetch them only when they become relevant.

Static loading: always on

All skills are loaded when the agent starts. Simple, predictable, and fast, because nothing has to be chosen at runtime.

Cost: unused skills waste context, and it will not scale to hundreds of skills.

Dynamic loading: only when relevant

A lightweight router matches the request to the few skills that fit, and activates just those. Context stays lean and the library can grow large.

Cost: the router can miss a relevant skill, and matching adds a little latency.

Think of it like apps on a phone. Static loading is keeping every app open at once. Dynamic loading is opening an app only when you need it, so the phone stays responsive.

In plain terms

Context windowThe limited space holding everything the agent can read at once.
Skill routerA small matcher that picks which skills fit the current request.
