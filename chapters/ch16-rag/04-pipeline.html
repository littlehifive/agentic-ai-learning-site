16.2 Core RAG architecture

Three moves: index, retrieve, generate

A RAG system has two phases. Once, ahead of time, it indexes the documents. Then, on every question, it retrieves the relevant pieces and generates an answer grounded in them.

Step 1

Index

Split documents into passages, turn each into a searchable form, and store them. Done once, offline.

→

Step 2

Retrieve

For the user's question, find the handful of passages most likely to contain the answer.

→

Step 3

Generate

Paste those passages into the prompt and ask the model to answer using only them, with citations.

Offline, once · build the index
Online, per query · retrieve then generate

In plain terms

CorpusThe full collection of documents the system is allowed to draw on.
Top-kThe small number of best-matching passages, often three to ten, handed to the model.
GroundedAn answer that traces back to the retrieved passages rather than the model's memory.
