16.7 Agentic RAG

Let the agent decide when and what to fetch

Plain RAG always retrieves once, then answers. That breaks on multi-step questions. In agentic RAG, the agent treats retrieval as an action it can choose: plan, retrieve, check if it has enough, and loop again if not.

Plan

Break the question into the separate pieces of information it actually needs.

→

Retrieve

Send each piece to the right source: documents, a database, the web, or code.

→

Evaluate

Ask whether the gathered context is now enough to answer well.

→

Generate

Once it is enough, write the grounded answer with citations.

Not enough yet? Refine the query and retrieve again
Think of it like a student who consults references mid-problem. Rather than grabbing one book up front, they realise partway through that they are stuck, look up exactly the missing fact, then continue.
