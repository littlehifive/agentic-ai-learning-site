24.8.1 & 24.11 The honest default

Most tasks are better as one good agent

This is the most important slide. A multi-agent system is not a free upgrade; it adds cost, latency, and failure points. Reach for it only after a single well-designed agent has proven it cannot keep up. The book's own advice: start simple, measure the limits, and add agents only when you must.

✕The task is simple enough for one agent. If a single prompt and a few tools do the job, stop there.
✕The roles are not really distinct. Five copies of the same assistant add cost, not skill.
✕Latency or budget is tight. Every extra agent and message adds tokens, time, and money.
✕You need easy debugging. More agents means more places to look when something goes wrong.
Think of it like staffing a job. You do not hire a five-person team to answer one email. You hire the team when the work genuinely splits into specialties, and even then you accept the overhead that comes with it.
