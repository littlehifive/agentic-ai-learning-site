24.1 Motivation: why multiple agents?

Reach for a team when one agent cannot hold it all

Use multiple agents when a task splits into clearly separate roles, or when it needs more context than one agent can keep in its head at once. Below that bar, a single well-designed agent is usually the better choice.

Four reasons to split the work

  • Specialization. A coder, a fact-checker, a writer each tuned for their job.
  • Parallelism. Independent sub-tasks run at the same time, not one after another.
  • Robustness. A second agent can verify or re-derive a shaky answer.
  • Emergent quality. Through debate and refinement, the group can exceed any one member.

What the team costs you

  • Coordination overhead. Every message between agents costs tokens, time, and money.
  • More failure points. More moving parts means more places things can break.
  • Harder to debug. When the group is wrong, finding which agent caused it is tricky.
Think of it like hiring. One brilliant generalist needs no meetings. The moment you hire a team, you gain specialists but you also gain standups, handoffs, and the chance that two people redo the same work.

In plain terms

Monolithic agentOne agent does the whole task; simple, but limited by its single context window.
Agent societyMany agents that divide the work and share results; more power, more overhead.
