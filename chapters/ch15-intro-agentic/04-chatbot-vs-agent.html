From single-turn response to control loop

The same model, used in two very different ways

The shift from chatbot to agent is not a bigger model or better wording. It is a change in shape: from one input and one output, to a process with memory, real effects, and a rule for when to stop.

Chatbot

One question in, one answer out

The model reads your message, produces a single response, and waits. It holds nothing of its own, changes nothing in the world, and never decides on its own that it is finished. Think of a function call: one input, one output.

Agent

A loop with state, effects, and a stop rule

The model runs a cycle: it keeps track of what it has done, takes actions that change real systems, and continues until a goal is reached or it asks for help. Think of a program with a loop, not a single call.

Think of it like asking a question at an information desk versus hiring an assistant. The desk gives you one answer and you leave. The assistant remembers the task, makes calls, books things, checks the results, and reports back when it is done.

In plain terms

StateMemory of what the agent has done, what worked, and what failed, carried across steps.
Side effectA real change the agent makes in the world: a file written, an email sent, a record updated.
Stopping conditionThe rule that ends the loop: the goal is met, or the agent hands off to a human.
