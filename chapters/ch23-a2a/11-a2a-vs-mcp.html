23.7 A2A versus MCP: complementary protocols

Two protocols, two directions, used together

A2A and MCP are often confused, but they solve different problems and pair naturally. MCP reaches downward from an agent to its tools and data. A2A reaches sideways from one reasoning agent to another.

MCP, the vertical protocol

  • Connects an agent to tools, databases, and code runners
  • Only the agent reasons; the other side is a deterministic service
  • Typically stateless, millisecond tool calls
  • Best for "search the web" or "run this query"

A2A, the horizontal protocol

  • Connects one agent to another agent as a peer
  • Both sides reason, plan, and use their own tools
  • Stateful tasks with a full lifecycle and streaming
  • Best for "delegate this to a specialist"
Think of it like a contractor who uses power tools to do the work themselves (MCP), but phones a licensed electrician when the job needs real expertise (A2A). One reaches for tools; the other calls a peer.

In plain terms

Use MCP whenThe other end is a fixed function the agent fully controls.
Use A2A whenThe other end must reason about the request and make judgment calls.
Use both whenAn orchestrator delegates via A2A, and each specialist reaches its tools via MCP.
