23.2.3 Task lifecycle

Every job is a task that moves through known states

A2A models all work as a task with a simple state machine. The caller can track exactly where a job stands at any moment and respond when the agent needs something.

Step 1

Submitted

The caller sends the task; the agent acknowledges it has received it.

→

Step 2

Working

The agent is processing. The caller can poll or wait for updates.

→

Step 3

Input required

The agent pauses to ask a clarifying question before it can go on.

→

Step 4

Completed

The task finished; the result is ready to collect.

Other endings exist too: a task can be failed if an error stops it, rejected if the agent declines, or canceled if either side aborts it.
Think of it like tracking an online order: placed, being prepared, a quick question about your address, then delivered. You always know which stage you are at.

In plain terms

TaskA unit of work with an ID and a current state you can check at any time.
PollingAsking again from time to time, "is it done yet?", until the task reaches a final state.
