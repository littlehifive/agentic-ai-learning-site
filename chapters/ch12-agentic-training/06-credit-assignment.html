12.8.3 Fine-grained credit assignment

If twenty steps end in failure, which one was to blame?

This is the hard part. When an agent takes twenty actions and the final test fails, a single terminal score of zero punishes all twenty equally, even the good ones. The work of training is figuring out which steps actually deserve the blame, or the praise.

A. Reward the checkpoints along the way

Hand out small rewards at deterministic milestones: the code compiles, the right page element is found, the query returns rows. Every step now gets a signal, not just the last one, which speeds up learning sharply.

B. Find the exact step that broke it

Replay the part that went right, locate the first move where things went wrong, and apply the negative reward only to that step. The already-correct steps are left untouched, so a good habit is not unlearned.

Think of it like reviewing the chess game afterwards. The whole game was lost, but you trace back to find the one blunder that cost it, and you keep the strong opening that came before.
