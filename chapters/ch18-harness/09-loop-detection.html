18.7.2 Loop detection and recovery

Notice when the agent is stuck

An agent left running can spin forever: calling the same tool with the same input, or flipping between two states. The harness watches for this and steps in, so the agent does not burn time and money going nowhere.

Cap the iterations

Set a hard limit, say fifty steps per task. If the agent reaches it, stop and report what it has so far.

Spot repeats

Fingerprint each tool call and its arguments. If the same call shows up too often in a short window, break the loop.

Check for progress

If the agent's state has not changed for several steps, treat it as stuck and trigger a recovery handler or a re-plan.

Think of it like a driver circling the same block. A passenger watching the route notices the loop, calls it out, and suggests a different turn, instead of letting the car go round forever.

In plain terms

Iteration guardA maximum number of steps, so a run always ends even when nothing works.
Action hashingTurning each tool call into a fingerprint to catch exact repeats in a sliding window.
