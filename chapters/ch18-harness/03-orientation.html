18.1 What is an agent harness?

The harness is the agent's operating system

A model is just a function from text to text. It has no memory, no clock, and no way to act in the world. The harness wraps it with the five things an agent actually needs, and keeps reasoning cleanly separate from running things.

Reasoning

The model

Decides what to do next. The harness never second-guesses its thinking.

Execution

Tools

Dispatches tool calls, handles input and output, and sandboxes them.

Memory

State

Holds the context window, a scratchpad, and a long-term store.

Communication

Routing

Passes messages between the model, the user, and other services.

Observability

Seeing in

Logs and traces every step so you can watch what the agent did.

Think of it like an operating system. Your apps do the work, but the OS gives them memory, files, a screen, and a way to talk to the network. The harness does the same for a language model.

In plain terms

HarnessThe runtime around the model that manages memory, tools, state, and recovery.
Separation of concernsThe model only reasons; the harness handles everything else around it.
