18.6 State management

The harness remembers where the agent is

A model on its own forgets everything between calls. The harness keeps the state, so a task can pause, resume, or roll back. Treat that state like a database schema: design it carefully up front, because changing it later is painful.

Conversation

The message history, with each turn's role, content, and metadata like its token count.

Task

Which subtasks are done or pending, plus checkpoints to resume after a failure.

Agent

The current plan, the actions still pending, and facts the agent has established.

Persistent

What carries across sessions: user profiles, long-term memory, and past task history.

Think of it like a save file in a long game. You can quit, come back tomorrow, and pick up exactly where you left off, because the game wrote down your progress, your inventory, and your location.

In plain terms

StateEverything the agent must remember to keep working across steps and sessions.
CheckpointA saved snapshot that lets a long task resume after a crash or pause.
