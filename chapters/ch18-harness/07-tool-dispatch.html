18.4 Tool integration and execution

The harness is the agent's hands

Tools are how the model acts in the world: searching the web, reading a file, running code. The model only asks for a tool by name. The harness does the rest, and treats every tool result as untrusted data, never as new instructions.

1

Pick

The model chooses a tool from clear descriptions of what each one is for.

→

2

Run

The harness runs it in a sandbox, with timeouts and limits to stay safe.

→

3

Clean

It validates and trims the result, since outputs can be huge.

→

4

Return

The cleaned result goes back into context for the next thought.

Think of it like a lab assistant. The scientist names an experiment to run; the assistant fetches the equipment, runs it behind a safety screen, tidies the results, and hands back a clean readout, without ever taking orders hidden inside the samples.

In plain terms

Tool descriptionA clear note on what a tool does and when to use it, the main signal for picking it.
SandboxingRunning tools in a walled-off space with limits, so a bad call cannot do harm.
